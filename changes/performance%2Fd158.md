The mixed-separator guard now keeps its refusal when a later part of a short record reads as a formatted measure, so a foreign record such as `Oct 1, 2026;A-100;$100;$10000` under a comma header is refused instead of loading and dropping its sales.

- `src/app/numbers.ts` reads each later other-separator part as a measure when it is a plain number or a formatted one the loader's own number reading accepts. `readsAsFormattedMeasure` repeats the reading `money()` and `northAmerican()` do in SQL, from the same pattern constants: one currency sign or code at either end, grouping marks folded only inside a whole group shape, brackets or a trailing minus for the sign, and dollar signs and spaces ignored before the cast. A currency code glued to the digits stays text, as it does in the loader. `MEASURE_FIELD` and every other condition in the guard are unchanged, so `2025,A;B;C;D` under a four-column comma header and product-only punctuation with empty trailing cells still load, and `2025,X;Y;10;100` stays refused.
- `12%` still loads, because the loader does not read a percent sign as a number.
- `test/numbers.test.ts` pins the dated-period file, the `2026,Q4;` record and its semicolon mirror through the decision, refuses the dated-period file through the real load guard, and checks the guard's answer against the loader's reading for `$100`, `100 $`, `1,000`, `1.000,50`, `(100)`, `12%`, `€100`, `100 EUR` and a plain word.
