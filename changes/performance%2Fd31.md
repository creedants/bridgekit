- The AI commentary panel now appears only for people who can use it. The build flag alone no longer decides it. The panel shows when the build has VITE_AI_COMMENTARY, the deployment's /api/config reports a commentary key, and the signed-in person has Pro on a workspace. A signed-out visitor and a deployment with no key see no panel, as does anyone whose config, session or plan read is still loading or failed. A signed-in person without Pro sees the panel heading and the sentence "A longer commentary written by Anthropic's Claude." with no button.
- The decision reads what the Workspace panel already fetched. src/app/useConfig.ts holds a small ledger that account.ts writes to after each call it already makes, so deciding the panel adds no request to any host and no request the page does not already make. The free static build imports none of it and adds no request.
- The server gate in server/commentary.ts and server/worker.ts is unchanged. Hiding the button is a courtesy, not the control. Nothing is sent to /api/commentary unless the button is pressed, exactly as before.
