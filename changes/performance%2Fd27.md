- A CSV that is not UTF-8 loads. A file from Excel's plain "CSV" export (Windows-1252) is decoded as Windows-1252 when the first 65,536 bytes hold a sequence that is not valid UTF-8, and a UTF-16 file is decoded by its byte-order mark, in the browser before the database reads it. A non-UTF-8 byte that appears only after that prefix, or that sits at its very end where it can look like the start of an unfinished UTF-8 character, leads to the sentence instead. A file that is already UTF-8 is handed over unchanged. A file whose text encoding cannot be read, or whose bytes contradict the encoding they declare, shows one sentence: `This file's text encoding could not be read. Save it as CSV UTF-8.`
