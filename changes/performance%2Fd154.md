A CSV with blank lines before its header, a date column that fails for two reasons, and a quoted header holding commas now load as the workbook and the existing notes already did.

- `src/app/db.ts` skips leading blank lines before the header, where a blank line is empty or holds only whitespace, commas, semicolons or the sniffed separator, and loads with the header and rows that follow. The skip is the count from the file prefix using that separator, passed as the reader skip in every staged read, so a header-only or empty file after blanks is still refused with no data rows and blank lines inside the data keep their existing handling. The header width check counts fields with quoting respected after those lines, so a correctly quoted header is not refused as too wide. `src/app/numbers.ts` takes the same skip for its dot planning read.
- `src/app/db.ts` names the first impossible calendar date by row order when a date column fails for more than one reason, so a column whose first failure is a bad time but which later holds an impossible date still gets the missing-date note with that value. Columns that already got a note keep the same value.
- `src/app/numbers.ts` reports the physical line for a mixed-style value, counting breaks inside quoted fields with CRLF as one, while logical record counts still match table ordinals. A truncated prefix that holds only part of the header is judged on what it holds. The sole header record is never discarded and its fields are counted with quoting respected.
- `test/numbers.test.ts` and `test/date-order.test.ts` cover the blank-lines load and its physical row, the whitespace-only, separator-only and pipe leading rows, the multiline-header physical row, the header-only refusal, the bad-time-first date note, and the quoted header field count and load including the truncated too-wide refusal.
