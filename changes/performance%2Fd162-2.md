- `.gitignore` ignores `.agents/` and `.cursor/`, so those directories no longer appear as untracked. `git status --short` no longer lists them at this head.
- `vite.config.ts` warns once after `loadEnv` when `process.env.VITE_WORKSPACES` is `1` and `env.VITE_PADDLE_CLIENT_TOKEN` is empty, printing `VITE_PADDLE_CLIENT_TOKEN is unset, so the Paddle checkout will not load.` The build still exits 0 and prints nothing when the token is set or when the build is not a workspaces build, which keeps `npm run build` quiet. The Cloudflare script sets `VITE_WORKSPACES=1`, so `npm run build:cloudflare` now says so too.
- The development `dev-commentary` plugin answers only a request whose `Origin` parses to an HTTP or HTTPS URL with the same host and port as the request's own `Host` header. Any other request, including one with no `Origin`, gets status 403 and the body `{"error":"Requests must come from this site."}` before the handler runs, so a page on another site cannot spend the local `ANTHROPIC_API_KEY`.
- The plugin still mounts only in `serve` and only when a commentary key is present, so production and the deployed Worker are unchanged.
- `test/vite-config.test.ts` calls the exported config function with `VITE_WORKSPACES=1` and checks one warning naming `VITE_PADDLE_CLIENT_TOKEN` and the checkout, none with a dummy token, and none without workspaces. The missing-token case sets the setting to the empty string, so a value in `.env.local` cannot supply it. It then mounts the plugin on a fake server whose `ssrLoadModule` is a stub and asserts that a cross-origin POST, a POST with no `Origin`, a same-host Origin with a non-HTTP(S) scheme, a malformed Origin, `Origin: null`, and a same-host Origin with a different port are each refused with 403 without reaching the handler, while a same-origin POST reaches it. These tests fail at base `d0b975d` and pass at this head.
