- `trustedProviders` in `server/auth.ts` no longer lists `microsoft`, so Better Auth will not link a Microsoft sign-in to an existing account by its unverified email. A sign-in whose email matches an existing account, and whose token does not mark that email verified, is now refused and sent to the sign-in error page with `account_not_linked`, instead of being signed in as that account. `google` stays trusted. `test/account-linking.test.ts` pins both providers in the built options and drives the real Microsoft callback with a fake provider, showing a matching email is refused, the existing account gains no account row, and the callback sets no session cookie.
