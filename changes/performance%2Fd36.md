- The Bridge tab gains a "Split by" control beside the "Preview" marker, whose first option is "None" and whose other options are every text column of the loaded file. Choosing a column runs `bridgeBy` over that column and draws a grid of small price-volume-mix bridges below the main one, one per value and one for everything the single panels leave out, in the engine's own order. Choosing "None" removes the grid and runs no extra query; the page then looks exactly as it did before.
- Every panel is drawn from its own `BridgeResult` with one value axis shared across the whole grid, so a bar's height means the same thing on any panel. The panels' charts go through one chart component that the main waterfall also uses, so there is one set of steps, colours and tooltip rules. When every bar stays at or above zero, the main waterfall renders exactly as before. A bar below zero is drawn from its low to its high, on the main waterfall and on a panel. A panel's title is the value itself, "(blank)" when the value is empty or null, and "All other values" for the combined panel. Clicking a bridged panel's title shows that value's bridge at full size, with the value's name as the way back to the grid. Opening that view moves focus to the way-back control. Closing it moves focus back to that panel's button, or to "Split by" when the button is gone. The full-size panel chart is named "Bridge for" plus the value. The main chart's name is unchanged.
- While the page shows "The setup changed since this bridge was calculated. Calculate again to update it.", a split is not calculated. A grid already on screen for the chosen column stays, because it still describes the bridge above it. Choosing another column, or "None", removes the grid until the next calculation.
- The page runs one database statement at a time, so a split, a recalculation, another tab and an Excel export cannot overlap. A column replaced before its split starts never runs. A file drop, a paste, and a sample's replacement of the loaded table wait until the current engine call has finished, and a split whose rows or calculation changed while it ran is not shown. A database start that fails is not remembered: the next split tries again, and shows "The small bridges could not be calculated." when the database still will not open. When a level is below zero, the main chart and the full-size panel start the axis at that level and draw every bar from its low to its high. The caption "Value axis starts at <value>, not zero, so the steps are visible." is shown when that axis does not start at zero, including below zero, and is absent when it does.
- A panel with no bridge of its own, because its value is new or sells no units, shows its prior and current sales and the words the page already uses for those cases. Nothing is recomputed in the page: the engine decides the panels, their order and the figures between them, and the page only formats what it is given.
- Under the grid the page states the one sentence the ticket dictates, followed by one signed figure per effect of the mix between values. A new calculation remounts the results view, so the chosen column survives a recalculation as a variable of the page's lifetime only: it is not written anywhere, and a reload starts again with no split.
